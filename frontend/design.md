# Pixel Arcade Plaza 프론트엔드 디자인 스펙

> 실제 구현의 기준은 `src/theme.css`와 각 feature의 컴포넌트/CSS다. 이 문서는 화면마다 같은 판단을
> 반복하지 않도록 현재 합의된 시각 언어와 상호작용 원칙을 정리한다. 수치가 코드와 달라지면 코드를
> 먼저 확인하고 이 문서를 함께 갱신한다.

## 1. 테마 방향

Cam-ON은 **Pixel Arcade Plaza**를 공통 허브로 사용한다.

- 메인 화면: 여러 미니게임 부스가 모인 광장으로 입장하는 장면
- 대기방: 다음 부스로 이동하기 전 쉬고 준비하는 광장 내부 공간
- 게임 화면: 각 게임의 개별 부스. 배경 화풍은 달라도 공통 상단 바와 참가자 색상 체계는 유지
- 중간 결과: 광장의 전광판/스코어보드
- 최종 결과: 축제의 파이널 우승 무대

배경 이미지만으로 테마를 설명하려 하지 않는다. 패널 외곽선, 단단한 픽셀 그림자, 픽셀 글꼴,
버튼 상태와 색상 의미가 모든 화면에서 이어져야 한다.

그림자는 흐린 블러보다 아래·오른쪽으로 밀린 단단한 픽셀 그림자를 사용한다. 같은 행의 버튼은
외곽선 두께, 그림자 거리, 모서리 반경을 통일한다.

## 3. 타이포그래피

- 기본: `Mona12`
- 대체: `Galmuri11`, `monospace`
- 한글·영문·숫자·참여 코드를 같은 픽셀 계열로 유지한다.
- 제목, 본문, 보조 문구는 크기뿐 아니라 색 대비로도 위계를 만든다.
- 버튼 라벨과 아이콘은 버튼 외곽선을 기준으로 수평·수직 중앙 정렬한다. 글자의 시각 중심을 맞추기
  위해 아이콘만 임의로 아래로 내리지 않는다.
- 긴 장치 이름이나 방 정보는 컨테이너를 늘리지 않고 말줄임표로 처리하며 전체 값은 title/tooltip로 제공한다.

## 4. 공통 컴포넌트

### 4.1 패널과 카드

- 밝은 패널: 크림/아이보리 배경 + 잉크 외곽선 + 5px 단단한 그림자
- 영상 카드: 참가자 색상 외곽선과 동일한 반경을 영상·하단 정보 바에 적용
- 콘텐츠가 줄거나 늘면 내부 요소만 이동하지 말고 부모 높이와 패딩을 함께 조정한다.
- 외곽선과 첫/마지막 요소 사이 여백은 같은 계열 카드에서 동일하게 유지한다.

### 4.2 버튼

- 주요 동작: 아케이드 오렌지
- 보조 동작: 밝은 크림
- 정보/선택: 아케이드 블루
- 방 나가기·강퇴·삭제: 코럴/오류 계열
- hover: 기본 위치에서 약 `-1px` 이동하거나 색 대비를 높인다.
- active: 그림자 방향으로 눌리며 그림자를 줄인다.
- disabled: 명도와 투명도를 낮추되 라벨은 읽을 수 있어야 한다.
- focus-visible: 아케이드 블루 또는 참가자 맥락 색상으로 명확한 외곽선을 제공한다.

### 4.3 입력창

- 크림 배경, 2px 잉크 외곽선, 6px 반경을 기본으로 한다.
- placeholder는 `--pap-text-muted`, 입력값은 `--pap-ink`를 쓴다.
- 입력 완료 여부에 따라 버튼 활성 상태가 바뀌어도 폭과 위치는 변하지 않는다.

### 4.4 공통 상단 바

- 왼쪽: Cam-ON 로고
- 오른쪽: 사운드 설정, 방 나가기 아이콘
- 로고 클릭과 방 나가기 아이콘은 같은 공통 확인 팝업을 연다.
- 대기방과 세 게임 화면의 높이·좌우 안전 여백·버튼 크기를 동일하게 유지한다.
- 배경은 화면별로 달라도 상단 바 자체의 컴포넌트 규격은 바꾸지 않는다.

### 4.5 사운드

- 공통 패널: **배경음악**, **효과음** 두 슬라이더만 표시한다.
- 아이콘 클릭 시 해당 항목을 0%로 만들고 음소거 아이콘으로 바꾼다.
- 트랙은 얇은 잉크색 진행 영역과 옅은 잔여 영역, 아케이드 블루 손잡이를 사용한다.
- 참가자 음량은 참가자 카드의 스피커 컨트롤에서 로컬로 조절한다. 전체 사운드 패널에 중복 표시하지 않는다.
- 상대 음소거 상태는 카드 우하단에 작게 유지하되 영상 내용을 가리지 않는다.

### 4.6 팝업과 토스트

- 공통 모달 배경: 전체 화면 잉크 55% + 약한 blur, `z-index: 100` 이상
- 방 나가기, 서버 연결 실패, 참가자 연결 확인은 공통 모달 규격을 사용한다.
- 토스트는 코드 복사, 링크 복사, 방장 위임처럼 짧은 완료 알림에 사용한다.
- 모달 내부 요소 묶음은 팝업 전체에서 수직 중앙에 가깝게 배치하고 위·아래 여백 차이가 과도하지 않게 한다.

## 5. 화면별 원칙

### 5.1 메인 화면

- 배경: `/assets/landing-bg.png`, `center bottom / cover`
- 중앙 로고, 안내 문구, 방 만들기/코드로 참여 버튼이 한 묶음으로 읽혀야 한다.
- 참가자 4색은 배경 레인과 브랜드 장식에만 사용하고 CTA는 오렌지/크림으로 구분한다.
- 코드 입력 → 닉네임 입력 → 대기방 흐름을 동일한 모달 규격으로 연결한다.

### 5.2 대기방

- 배경: `/assets/lobby-quiet-pixel-plaza-bg.png`, `cover`
- 2인: 2열 1행. 3인: 위 2명 + 아래 중앙 1명. 4인: 2×2.
- 빈 슬롯은 문장·링크를 반복하지 않고 비어 있음을 명확히 보여준다.
- 발화자는 해당 참가자 색상의 굵은 네온 외곽선으로 표시한다.
- 방장은 참가자 카드에서 강퇴와 음량을 각각 조작하고, 일반 참가자는 상대 음량만 조절한다.
- 게임 구성 빈 상태는 점선 안내 영역과 “오른쪽 게임 목록에서 + 버튼을 눌러 세트를 추가해 주세요.” 문구를 사용한다.
- 참여 코드는 티켓 형태를 유지하며 코드 복사/링크 복사 상태는 토스트로 피드백한다.

### 5.3 환경 설정

- 카메라·마이크·스피커 장치 선택은 동일한 높이와 글자 크기를 사용한다.
- 긴 장치명은 말줄임표, 펼친 목록에서는 전체 이름을 확인할 수 있게 한다.
- 테스트 결과 카드는 손동작 인식, 사물 인식, 마이크 입력, 스피커 출력을 동일한 카드 규격으로 배치한다.
- 카메라가 없거나 권한이 없으면 손동작·사물 인식을 정상으로 표시하지 않는다.
- `CAM, ON! DEVICE CHECK` 같은 장식 문구보다 상태와 재시도 동작을 우선한다.

### 5.4 게임 구성

- 왼쪽은 세트 구성, 오른쪽은 게임 리스트와 상세 설명이다.
- 세트 수는 최대 7개이며 가득 차면 추가 동작을 비활성화한다.
- 게임별 규칙 표기: 물건 찾기 `5라운드`, 닌자 `최종 1인까지`, 몸으로 말하기 `N라운드`.
- 게임 카드 클릭 시 아코디언으로 설명을 펼치고, hover/expanded hover는 배경을 채우지 않고 외곽선만 강조한다.
- 스크롤 영역 상·하단은 동일한 안전 여백을 두고 마지막 카드가 자연스럽게 일부 보이도록 한다.

### 5.5 게임 화면

- 각 게임 배경은 개별 부스의 분위기를 가질 수 있다.
- 공통 상단 바, 참가자 색상, 발화 테두리, 참가자 음량 컨트롤, 방 나가기 팝업은 동일하게 유지한다.
- 라운드 결과는 상단 안내와 일시적 팝업을 함께 사용하며, 팝업이 사라진 뒤 상태도 설계한다.
- 영상 위 장식은 얼굴·손·물건 인식 영역을 가리지 않는다.

### 5.6 중간 결과

- 일반 게임 세트 점수는 18칸 분절 바와 빈 칸을 함께 순차적으로 나타낸다.
- 동점자는 같은 순위를 표시하며 모든 행이 동일한 칸 수와 애니메이션 타이밍을 사용한다.
- 닌자 게임은 1~4위 단상형 결과를 사용하고 `5p / 3p / 2p / 1p`를 표시한다.
- 누적 순위는 레이스 트랙과 참가자 색상 깃발로 표현한다. 참가자 색은 순위 변화와 무관하게 유지한다.
- 마지막 세트에는 빈 버튼 공간 대신 최종 결과 집계 안내를 표시한다.

### 5.7 최종 결과

- 우승자 영상은 가장 크게, 나머지 3명은 한 행에 배치한다.
- 영상 프레임과 배경 이미지의 슬롯 크기·모서리 반경이 정확히 맞아야 한다.
- 최종 순위 카드의 좌우 여백과 행 간격을 동일하게 유지한다.
- 발화 테두리는 대기방에서 배정된 참가자 색상을 그대로 사용한다.
- 하단 동작은 대기방으로 돌아가기와 방 나가기를 같은 행에 두고 의미를 색으로 구분한다.

## 6. 배경과 이미지 자산

- 일반 배경은 화면 전체에서 `cover`를 기본으로 하되 주요 UI 안전 영역이 잘리지 않도록 원본 구도를 설계한다.
- 결과 무대처럼 배경 슬롯과 HTML 요소를 맞추는 화면은 고정 비율 배치를 우선한다.
- 픽셀 이미지는 브라우저에서 불필요하게 흐려지지 않도록 정수 배율과 `image-rendering` 적용 여부를 확인한다.
- 배경 안에 이미 그려진 슬롯과 실제 HTML 카드가 겹치는 화면은 원본 슬롯의 크기와 반경을 먼저 맞춘다.
- 장식 이미지는 콘텐츠보다 앞에 오지 않는다. 특히 영상 카드, 정답 입력, 타이머 주변은 비워 둔다.

## 7. 반응형과 Auto Layout 대응

- 기준 데스크톱 화면은 16:9지만, CSS는 화면 높이와 참가자 수 변화에 대응해야 한다.
- 큰 영역은 grid/flex로 구성하고 화면 전체를 절대 좌표로 조립하지 않는다.
- 카드 내부는 부모 패딩, 요소 간 gap, 최소 높이를 명시한다.
- 텍스트 증가 시 버튼/카드가 겹치지 않도록 `min-width`, `min-height`, `text-overflow`를 사용한다.
- 오버레이와 팝업은 viewport 기준 중앙에 고정하고 부모 transform/overflow에 종속되지 않게 한다.

## 8. 상태와 접근성 체크리스트

- [ ] default / hover / active / focus-visible / disabled 상태가 있는가
- [ ] 로딩 / 빈 상태 / 오류 / 권한 필요 / 연결 끊김 상태가 있는가
- [ ] 2·3·4인과 빈 참가자 슬롯을 확인했는가
- [ ] 동점, 마지막 세트, 최대 7세트를 확인했는가
- [ ] 닉네임만 노출되고 내부 ID가 보이지 않는가
- [ ] 참가자 색상이 대기방부터 최종 결과까지 유지되는가
- [ ] 버튼 아이콘과 라벨이 외곽선 기준 중앙 정렬됐는가
- [ ] 외곽선과 첫/마지막 요소의 상하좌우 여백이 균형 잡혔는가
- [ ] 키보드 포커스와 `aria-label`이 있는가
- [ ] `prefers-reduced-motion`에서 핵심 정보가 사라지지 않는가

## 9. 구현·QA 기준

- 디자인 토큰은 `src/theme.css`를 단일 출처로 사용한다.
